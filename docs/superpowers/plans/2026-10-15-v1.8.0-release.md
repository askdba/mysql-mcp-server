# v1.8.0 Release Plan

**Goal:** Ship a security and compatibility release: Go 1.26 with patched dependencies, and CI coverage for every MySQL/MariaDB version in current use (MySQL 8.0, 8.4, 9.7, 26.7; MariaDB 11.4, 12.3).

**Why a minor bump (1.8.0, not 1.7.2):** building from source now requires Go 1.26 (`go.mod`), and the CI-supported version set changes (MySQL 9.0 dropped, 9.7/26.7/MariaDB 12.3 added). Runtime behavior and the MCP tool surface are unchanged.

**Branch:** `fix/compat-security-v1.8` (5 commits on top of `main` @ `8607a86`).

## What is in the release

| Area | Issue found | Fix |
|---|---|---|
| Security | Go 1.24 is EOL; govulncheck: 37 reachable vulns (stdlib, `x/crypto` SSH DoS, go-sdk GO-2026-5771) | Go 1.26; `x/crypto` v0.58.0, go-sdk v1.8.0, mysql driver v1.10.1, testcontainers v0.44.0 → 0 reachable vulns |
| CI | `govulncheck@latest` needs Go 1.26 → step silently failing (`continue-on-error`) | Pinned `govulncheck@v1.9.0` on Go 1.26 |
| CI | `.golangci.yml` in v1 format → golangci-lint v2 refused to run (silently) | Migrated to v2 format; lint v2.14.0; 0 issues |
| CI | gosec pinned to v2.23.0 only because of Go 1.24 | gosec v2.29.0; findings triaged, 0 open |
| CI | Sakila DB never loaded in CI → all Sakila tests skipped | Loaded via the service image's own client; 13 Sakila tests now run per job |
| CI | Matrix missing 9.7 LTS successor coverage, 26.7, MariaDB 12.3; 9.0 EOL | MySQL 8.0/8.4/9.7/26.7, MariaDB 11.4/12.3 |
| Tests | testcontainers test panicked without Docker, pinned `mysql:8.0.36`, failed on MariaDB (wait strategy) | Skips without Docker; `MYSQL_TC_IMAGE`; MariaDB-compatible wait |
| Dev UX | Fixed compose host ports (3307/3310…) clash with local servers | All ports overridable (`MYSQL84_PORT=…`); new 9.7/26.7/MariaDB 12 services + make targets |

## Verified locally (2026-10-15, before opening the PR)

- `go build`, `go vet` (incl. `-tags=integration`), `go test -race` — pass on Go 1.26.9
- golangci-lint v2.14.0: 0 issues · gosec v2.29.0: 0 findings · govulncheck v1.9.0: 0 reachable vulns
- Simulated `qa.yml` integration jobs (bare service container + `docker exec` fixture load + full `-tags=integration` suite incl. testcontainers): **0 failures** on mysql 8.0, 8.4, 9.7, 26.7, mariadb 11.4, 12.3
- Docker image builds on `golang:1.26-alpine` and runs
- Stdio MCP smoke test of the built binary against MySQL 26.7: initialize, tools/list, `server_info`, `run_query`; `DELETE` rejected by the read-only guard

## Steps

### 1. PR
- [ ] Push `fix/compat-security-v1.8`, open PR against `main` (body: summary table above).
- [ ] Wait for **Go CI** and **QA Pipeline**. First-run risks to watch:
  - `mysql:26.7` / `mariadb:12.3` service images pulling on GitHub runners.
  - `golangci-lint-action@v7` downloading v2.14.0.
- [ ] Address bot review findings (correctness/security/regressions).
- [ ] Merge.

### 2. Release candidate
- [ ] On `main`: rename `## [Unreleased]` → `## [1.8.0-rc.1] - <date>` in `CHANGELOG.md`, add a fresh empty `## [Unreleased]`.
- [ ] `git tag -a v1.8.0-rc.1 -m "Release candidate v1.8.0-rc.1"` and `git push origin v1.8.0-rc.1`.
- [ ] Confirm `release.yml` completes: binaries (GoReleaser), Docker image push, README version-bump bot commit.

### 3. Validate the RC
- [ ] Install the RC binary / pull the RC Docker image and connect it as an MCP server to each host instance (MySQL 8.4, 9.7, 26.7, MariaDB 12.3): `list_databases`, `describe_table`, `run_query`, `explain_query`, `server_info`.
- [ ] Spot-check SSH tunnel mode (`make test-integration-ssh`) since `x/crypto/ssh` moved 15 minor versions.
- [ ] Check `homebrew/mysql-mcp-server.rb` (still says `1.7.0-rc.1`) and update if the tap is maintained from this repo.

### 4. GA
- [ ] `CHANGELOG.md`: `## [1.8.0] - <date>` (fold rc notes), tag `v1.8.0`, push.
- [ ] GitHub release notes: lead with "Security: Go 1.26 + dependency updates (37 → 0 reachable vulns)" and "Build from source now requires Go 1.26".
- [ ] Refresh the backlog snapshot in `workflow.md`.

## Follow-ups (not in this release)

- MySQL 8.0 reached EOL in April 2026; keep it in CI while users still run it, and announce a deprecation timeline in the 1.8.0 notes.
- Consider making the govulncheck job **blocking** now that it is clean, so regressions like the one fixed here cannot recur silently.
- Remaining lint findings that only appear with `-tags=integration` are style-only (`sqlclosecheck` "Close should use defer", one `ST1023`); CI does not lint with that tag.
