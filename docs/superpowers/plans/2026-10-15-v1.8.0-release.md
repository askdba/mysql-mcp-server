# v1.8.0 Release Plan

**Goal:** Ship a security and compatibility release: Go 1.26 with patched dependencies, and CI coverage for every MySQL/MariaDB version in current use (MySQL 8.0, 8.4, 9.7, 26.7; MariaDB 11.4, 12.3).

**Why a minor bump (1.8.0, not 1.7.2):** building from source now requires Go 1.26 (`go.mod`), and the CI-supported version set changes (MySQL 9.0 dropped, 9.7/26.7/MariaDB 12.3 added). Runtime behavior and the MCP tool surface are unchanged.

**Branch:** `fix/compat-security-v1.8` (PR [#133](https://github.com/askdba/mysql-mcp-server/pull/133), based on `main` @ `8607a86`).

## What is in the release

| Area | Issue found | Fix |
|---|---|---|
| Security | Go 1.24 is EOL; govulncheck: 37 reachable vulns (stdlib, `x/crypto` SSH DoS, go-sdk GO-2026-5771) | Go 1.26; `x/crypto` v0.58.0, go-sdk v1.8.0, mysql driver v1.10.1, testcontainers v0.44.0 → 0 reachable vulns |
| CI | `govulncheck@latest` needs Go 1.26 → step silently failing (`continue-on-error`) | Pinned `govulncheck@v1.9.0` on Go 1.26 |
| CI | `.golangci.yml` in v1 format → golangci-lint v2 refused to run (silently) | Migrated to v2 format; lint v2.14.0; 0 issues |
| CI | gosec pinned to v2.23.0 only because of Go 1.24 | gosec v2.29.0; findings triaged, 0 open |
| CI | Sakila DB never loaded in CI → all Sakila tests skipped | Loaded via the service image's own client; 13 Sakila tests now run per job |
| CI | Matrix missing 9.7 LTS successor coverage, 26.7, MariaDB 12.3; 9.0 EOL | MySQL 8.0/8.4/9.7/26.7, MariaDB 11.4/12.3 |
| Tests | testcontainers test panicked without Docker, pinned `mysql:8.0.36`, failed on MariaDB (wait strategy) | Skips without Docker; `MYSQL_TC_IMAGE`; MariaDB-compatible wait |
| Dev UX | Fixed compose host ports (3307/3310…) clash with local servers | All ports overridable (`MYSQL84_PORT=…`); new 9.7/26.7/MariaDB 12 services + make targets |

## Follow-ups (not in this release)

- **MySQL 8.0 stays fully supported; no deprecation is planned** (maintainer decision, 2026-10-18). Oracle ended 8.0 support in April 2026, but many users have not migrated to 8.4 yet. Keep 8.0 in the CI matrix and the supported-versions lists.
- ~~Make govulncheck blocking~~: done in #134 (blocking in QA and the release gate, scanning every release target). QA Summary is now a required check on `main`.
- **Keep GoReleaser `brews`** even though it is deprecated in favor of `homebrew_casks` (maintainer decision, 2026-10-18): it still works, and migrating would make existing users reinstall as a cask, with limited Linux support. Revisit only if GoReleaser removes `brews`.
- Remaining lint findings that only appear with `-tags=integration` are style-only (`sqlclosecheck` "Close should use defer", one `ST1023`); CI does not lint with that tag.
