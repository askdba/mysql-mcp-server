# v1.7.1-rc.1 Release Preparation — Design

**Date:** 2026-06-04  
**Target version:** v1.7.1-rc.1  
**Author:** Alkin Tezuysal

---

## Context

v1.7.0 GA shipped 2026-04-19. Since then, three commits landed on `main`:

| Commit | Description |
|--------|-------------|
| `5a9e25f` | Security fix: `MYSQL_MCP_ALLOW_SYSTEM_SCHEMAS` opt-in + `ValidateDatabaseAccess` closes the `USE <db>` bypass; `explain_query` now runs `ValidateSQLCombined` (PR #132) |
| `fef94ce` | CI: `actions/checkout` and `actions/setup-go` upgraded to v6 (Node 24) |
| `3ae26b3` | CI: `golangci-lint-action` upgraded to v7, `codecov-action` to v6 (Node 24) |

The `CHANGELOG.md` already has an `[Unreleased]` section describing the security fix.

## What ships in v1.7.1

- **Security:** `MYSQL_MCP_ALLOW_SYSTEM_SCHEMAS` opt-in and `ValidateDatabaseAccess` gate (user-facing)
- CI action upgrades are infrastructure-only and do not appear in the user-facing CHANGELOG

## Approach

Cut the RC directly from `main` (Option A). No release branch needed — `main` is clean and no v1.8 feature work is in flight.

## Steps

1. **Update `CHANGELOG.md`**
   - Rename `## [Unreleased]` → `## [1.7.1-rc.1] - 2026-06-04`
   - Add a new empty `## [Unreleased]` section at the top

2. **Commit** the CHANGELOG update to `main`

3. **Tag and push**
   ```bash
   git tag -a v1.7.1-rc.1 -m "Release candidate v1.7.1-rc.1"
   git push origin v1.7.1-rc.1
   ```

4. **Watch CI** — GoReleaser fires on the tag push; confirms pre-release GitHub Release and Docker image push

## Success criteria

- `v1.7.1-rc.1` GitHub Release is marked as pre-release
- Docker image pushed to `ghcr.io/askdba/mysql-mcp-server:v1.7.1-rc.1`
- CHANGELOG on `main` reflects the versioned section with correct date
- No user-facing behavior changed relative to PR #132 (same code, just tagged)
